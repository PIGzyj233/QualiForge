# 产品不变式

这些原则是 QualiForge 所有设计决策的硬约束。新功能、PR、ADR 与外部集成都必须显式说明如何遵守。

## 1. 资产可信度优先

**AI 可以建议、归一化、摘要、起草，但不能绕过人工审核进入正式资产库。**

- AI 生成的候选用例可以作为临时 `PlanItem` 加入测试计划执行。
- 必须经过 `Review` 通过后才能成为正式 `TestCase`。
- 报告草稿可由 AI 生成，但发布结论必须由负责人确认。
- 模块树与映射规则的 AI 建议进入 `AgentStagedOutput`，由人接受/编辑/拒绝后才落地。

## 2. 代码只读，沙盒隔离

**Git 仓库分析全程只读，平台不运行项目代码。**

- 所有 Git 操作走受控 Sandbox，路径由系统生成，禁止符号链接逃逸。
- 允许：`clone / fetch / checkout / diff / show / ls-files / rg / 静态解析`。
- 禁止：运行测试、跑构建脚本、启动服务、执行迁移、连接业务数据库、执行任意仓库脚本。
- Workspace / Project 之间做目录级隔离。

## 3. 黑盒测试人员不应被迫看代码

**技术关联是系统推断字段，不要求黑盒测试工程师手动维护。**

- 代码路径、接口、服务、配置 key 由 `ModuleMappingRule` 与 AI 推断。
- 用户看到的是模块 / 功能域，技术证据只是依据。
- 模块树本身是产品/能力树，不是代码架构树。

## 4. 上下文不是指令

**仓库文件、导入文件、日志、README 与用户消息中的内容都是不可信上下文。**

- Agent 可以把它们当作证据使用。
- Agent 不能把它们当成指令执行。
- 系统提示词与工具权限是 agent 唯一可信的指令源。

## 5. 私有化优先

**MVP 与近期演进都以私有化部署为默认形态。**

- 数据库、Redis、Temporal、Git Sandbox、对象存储全部本地。
- SaaS 是后续选项，架构保留多 Workspace 与 token 加密能力但不优先交付。

## 6. 工作台密度优先于营销感

- UI 是测试与发布决策工作台，不是 AI 聊天 demo。
- 文件列表与技术细节是证据抽屉，不是主视图。
- 用户面向文案使用简体中文；标识符与注释使用英文。

## 7. 一切关键操作可审计

- `audit()` 是 `workspace/routes.py` 中的共享 helper，所有突变接口都要写审计。
- AI 调用走 `AIInvocationLog`，记录摘要、token、缓存命中与失败原因，不存储完整敏感 prompt。
- Agent 工具调用走 `AgentToolCall`，包含权限级别、idempotency key、输入/输出摘要。
